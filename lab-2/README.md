# Работа 2. Мониторинг API заказов

На стенде работает тестовый API заказов из [проекта первой работы](../report.md). Он возвращает тестовые ответы и позволяет вызвать ошибку, задержку или нагрузку.

## Запуск

Запустите Docker в режиме Linux-контейнеров. Из корня проекта выполните:

```sh
cd lab-2
docker compose up -d --build
```

Откройте [страницу API заказов](http://127.0.0.1:18280) и подождите около минуты. За это время Prometheus соберет первые метрики, а Loki начнет принимать записи. Откройте [Grafana](http://127.0.0.1:18300/d/bookshop-orders/bookshop-orders) для графиков и журналов, [Jaeger](http://127.0.0.1:18686) для трассировок и [Alertmanager](http://127.0.0.1:19093) для оповещений. Все адреса локальные. Grafana открывается в режиме просмотра.

| Кнопка | Ответ API | Что проверить |
| --- | --- | --- |
| Create error | HTTP 503 | В Grafana есть запись об ошибке, в Jaeger есть трассировка этого запроса |
| Create delay | HTTP 200 примерно через 2 с | В Jaeger видна медленная операция. На графике растет p95 |
| Generate load | HTTP 202 | API отправляет себе 60 запросов к списку заказов. На графике растет частота запросов |

Для проверки всех трех оповещений нажмите **Create error** восемь раз, затем **Create delay** семь раз. Каждый раз дождитесь ответа. После этого один раз нажмите **Generate load**. Уложитесь в минуту. Через 10-15 с откройте Alertmanager. Когда эти запросы выйдут из минутного окна, оповещения закроются.

## Что измеряем и когда приходит оповещение

Prometheus опрашивает `/metrics` и проверяет правила каждые 5 с. Графики и правила используют данные за последнюю минуту. Пороги рассчитаны на локальный стенд.

| Панель Grafana | Порог | Зачем следить |
| --- | --- | --- |
| Request rate | `OrderTrafficSpike` при частоте выше 0,5 запроса/с | Резкий рост нагрузки может занять все обработчики |
| Error rate | `OrderErrors`, если более 5% ответов имеют статус 5xx | Часть запросов покупателей завершается ошибкой |
| Response time (p95) | `SlowOrders`, если p95 выше 1 с | Часть покупателей долго ждет ответа, хотя большинство запросов проходит быстро |

p95 считают по гистограмме. Это оценка времени, за которое успевают завершиться примерно 95% запросов. В Jaeger видна длительность отдельного запроса.

Alertmanager отправляет оповещения на локальный адрес `/alerts`. Получатель записывает имя правила и статус `firing` при срабатывании или `resolved` при закрытии. Чтобы найти записи в Loki, используйте запрос:

```logql
{service="orders-api"} |= "Alertmanager notification"
```

## Как найти один запрос в Grafana и Jaeger

1. Нажмите **Create error**. API запишет ошибку в JSON-журнал. Alloy отправит запись в Loki.
2. На нижней панели Grafana откройте запись и скопируйте `trace_id`.
3. Найдите по этому идентификатору запрос в Jaeger. У него будет статус HTTP 503.
4. Нажмите **Create delay**. В Jaeger выберите сервис `orders-api` и операцию `POST /api/orders/slow`. Этап `slow-dependency` займет около двух секунд.

Flask передает трассировки в Jaeger через OpenTelemetry по OTLP/HTTP.

## Остановка и повторный запуск

В папке `lab-2` выполните `docker compose stop`. Для повторного запуска используйте `docker compose start`. Jaeger хранит трассировки в памяти. После перезапуска нажмите кнопки еще раз.
